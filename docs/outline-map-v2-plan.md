状态：代码及自动化复审已完成（2026-09-11）；P8 人工内容、桌面视觉与真实模型验收待完成。逐项修复和验证见 [复审报告](outline-map-v2-review.md)。

范围：论文／教材的总图与局部图、六份中文提示词、生成流水线、协议、引用、画布和兼容迁移。
关联：[现行地图合同](full-outline-v1.md)、[提示词目录](prompts.md)、[上下文管理](context-management.md)、[后端加固](backend-hardening.md)、[开发入口](agent-onboarding.md)。

> 核心原则：让模型结合全文，同时决定哪些内容值得成为节点、节点之间是什么关系，并允许在构图和复核过程中调整结构。应用提供原文、稳定的数据格式与可核对的引用，不预先规定论文必须长成哪一种图。

## 1. 执行边界与已确认方向

### 1.1 已确认的产品方向

1. 节点与关系联合设计，取消“先冻结论证单元，再被动把单元连起来”的新版本流程。
2. 模型自主选择节点数量、粒度、角色、关系名称、分支、汇合和分组。
3. 关系以模型生成的中文自然语言表达，不再要求属于固定 relationClass 枚举。
4. 节点角色允许自由命名，也允许不设置角色标签。
5. 不强制所有节点连通，不要求完整语义图无环；允许有依据的反馈、回指和相对独立的内容组。
6. 总图采用“整体构图 → 检查与定稿”，第二阶段可以调整整张地图。
7. 保留总图和按需生成的局部图两层；局部图围绕一个认识展开内部结构。
8. 所有新提示词使用完整中文稿，采用清楚的标题、列表和字段说明，不缩减为几句原则。
9. 功能、协议、校验、生成代码和画布需要一起调整，不能只换提示词。
10. 保留原文依据和不确定性说明，让读者能够核对节点及连线。

### 1.2 本计划对实现细节的默认选择

以下是为了让实施者能够直接开工而给出的技术默认，不应误称为用户逐字段确认的历史结论：

- 产品称“地图 V2”，新数据与生成协议使用 v4，以区别当前 outline-*-v3。
- 保留三个既有提示词存储槽 ID，通过协议元数据区分新旧含义。
- 总图正常两次模型调用，全任务共享最多一次额外修复额度；局部图正常一次，最多一次修复。
- 默认从 PDF-only 来源根独立生成，不自动读取 Brief、术语表、符号表、Discussion 或旁批。
- 新图用自由文本关系和可选自由角色；取消模型必须填写的固定重要性分类与数字 confidence。
- 分组为可选的平面语义分组，不增加第三层地图生成。
- 兼容旧成果、旧任务和旧自定义提示词，不通过清空工作区或强制恢复默认完成升级。

实现时可以调整内部模块名称或等价的数据表示，但不得恢复固定语义枚举、强制连通、强制无环、强制节点配额，或丢失用户数据。技术方案变化须记录理由与影响。

### 1.3 本次交付范围

- 新总图及新局部图完整生成闭环。
- 论文／教材各三份提示词，共六份。
- 新旧协议并存与明确分派。
- 来源根复用、冻结计划、付费结果恢复、原子发布。
- 自由关系显示、节点／连线详情、回路与多分量布局。
- 自动化验证、离线内容样本、桌面视觉验收与真实模型验收记录。

不包含跨论文知识库、无限层子图、自动预生成所有局部图、任意手工编辑学术关系、额外聊天系统或通用窗口管理器。

## 2. 产品目标与使用体验

### 2.1 功能分工

| 功能 | 主要回答 |
| --- | --- |
| Brief | 这份文档最值得理解和记住什么？ |
| 精读路线 | 按照什么顺序、用什么方法阅读？ |
| 论文论证地图 | 问题、设计、证据、结论和边界如何联系？ |
| 教材知识脉络图 | 概念、前提、推导、方法和应用如何依赖？ |
| 解释／Lens | 当前段落、公式、图或表具体是什么意思？ |
| 局部图 | 选中认识的内部结构怎样成立或运作？ |

地图应让读者能执行三个动作：

1. 从节点标题辨认具体内容。
2. 沿连线理解内容之间的关系。
3. 点开节点或连线，回原文核对。

### 2.2 节点粒度

指导性原则：

- 一个节点承载一个有意义、可独立表述的认识，或一个理解结构必需的内容对象。
- 标题尽量表达具体内容；takeaway 补足对象、条件、范围及必要结果。
- 可以分别验证、分别质疑或支撑不同结论的内容，适合拆分。
- 重复表达同一认识的材料适合合并；同一节点允许有分散在不同页的来源。
- 模型可以根据建立关系时发现的问题，重新选择节点。
- 总图保留整体理解必需的内容，局部图承载选中认识的细节。
- 概念、问题、对象型节点可使用准确的名词短语，不硬性要求每个标题都是结论句。

不得以章节数、页数或固定“10–18 个节点”等阈值判定内容合格；较长文档可以产生更大的图，较简单文档允许单节点或短链。

### 2.3 连线含义

- 连线标签由模型生成，读成“起点—关系—终点”时应意思明确。
- 关系说明解释为什么相连，必要时区分作者直接表述与基于原文的结构归纳。
- 不把支持写成证明、相关写成因果、例子写成普遍结论。
- 对比或对称联系允许无向边；依赖、转化、支持等有方向的联系使用有向边。
- 仅仅共享主题不自动成为连线理由。
- 不要求为孤立组补上“相关”“进一步说明”等连接词。
- 关键限制、反向证据和替代解释在默认视图可见。

## 4. 新协议与数据模型

### 4.1 协议标识

建议标识：

| 对象 | 标识 |
| --- | --- |
| 持久化图语义 | outline-map-v4 |
| 总图候选生成 | outline-draft-v4 |
| 总图检查定稿 | outline-review-v4 |
| 局部展开 | outline-deep-dive-v4 |

产品版本与数据库全局 schema 号互相独立。不得仅为提示词换代提升全局数据库版本；若确需新增表或列，沿用项目允许的兼容迁移与备份流程。

新任务 payload 必须显式写协议。旧任务缺少新标识时，仅在符合已知旧任务形状时走 v3；无法识别或未来版本须在付费前报错，不能猜测。

### 4.2 模型输出与应用元数据分离

模型负责 graph。审稿阶段另可输出 reviewNotes，记录重要修正及剩余疑点。

应用负责 protocolVersion、documentRevision、ocrRevision、route、model、promptDigest、planId、publishId、reviewStatus、usage、定位 bbox 等元数据。不能要求模型编造这些值。

候选阶段建议返回：

~~~json
{
  "graph": {
    "title": "文档内容关系图",
    "summary": "用简短文字说明这张地图主要呈现哪些结构。",
    "nodes": [],
    "edges": [],
    "groups": [],
    "gaps": []
  }
}
~~~

检查定稿阶段返回同结构 graph，并可附加 reviewNotes 数组。该数组是简短的结果说明，不要求逐步思考过程，也不作为节点或原文证据。

局部图使用相同图语义，父修订与选中节点 ID 由请求和持久层绑定。

### 4.3 节点字段

| 字段 | 要求 | 含义 |
| --- | --- | --- |
| nodeId | 必填、图内唯一 | 稳定引用标识 |
| title | 必填、非空 | 足以识别具体内容 |
| takeaway | 必填、非空 | 完整表达该节点的认识，保留改变含义的条件 |
| roleLabel | 可选，自由文本 | 如关键假设、竞争解释、观测异常；不设词表 |
| references | 必填且至少一项有效定位 | 内容出处及其在此节点中的作用 |
| uncertainty | 可选，自由文本 | 具体缺口或不确定性；没有时为空 |

v4 不要求 roleClass、固定 importance、sourceUnitIds 或数字 confidence。候选图本身就是复核输入，无须继续维护前置 units 池。重要条件优先放入 takeaway，不能只藏在 uncertainty。

如果之后确有“突出主要节点”需求，先采用用户选择或展示策略，不把固定角色／重要性配额重新写回模型契约。

### 4.4 关系字段

| 字段 | 要求 | 含义 |
| --- | --- | --- |
| edgeId | 必填、图内唯一 | 关系标识 |
| sourceNodeId | 必填 | 起点，必须存在 |
| targetNodeId | 必填 | 终点，必须存在 |
| direction | directed 或 undirected | 只表达箭头有无，属于技术格式 |
| label | 必填、非空、自由文本 | 本文具体关系 |
| rationale | 必填、非空 | 关系理由、必要条件及归纳性质 |
| references | 必填且至少一项有效定位 | 支撑关系判断的原文出处 |
| uncertainty | 可选，自由文本 | 该联系的具体限制 |

- 取消 relationClass 和 narrative／cross_link 作为 v4 语义必填项。
- direction 的有限取值不等于给学术关系分类。
- 作者没有直接写出的结构联系，可以引用两端相关材料，在 rationale 中说明是结构归纳。
- 不允许用全篇摘要、相同主题或模型自评代替具体依据。
- 相同端点可以有不同关系；不得仅按端点合并。
- 自环可表达有依据的自反馈等含义，不能因图形不方便而自动删除；无意义自环由内容复核指出。

### 4.5 引用结构

建议 references 的每项含：

| 字段 | 含义 |
| --- | --- |
| blockId | 可为空；只能来自本次冻结目录 |
| pageNumber | PDF 物理页码；有 blockId 时由本地核对对应页，无 blockId 时必须提供 |
| purpose | 自由文本，说明这处原文在这里提供什么 |

默认优先 block 定位。原生 PDF 能读到内容、OCR 无可用 block 时允许页级引用；页码必须在冻结 PDF 的有效范围内，界面明确显示“页级定位”。

校验规则：

1. blockId 与 pageNumber 至少提供一项可用定位。
2. 同时提供两者时必须一致；不能悄悄把错误页码换成正确值后当作原稿无误。
3. 模型不输出 bbox、路径、可执行链接或虚构截图坐标；应用从 OCR 建立跳转。
4. 引用数组可以指向同一文档中多个分散位置。
5. purpose 以自由文本区分“内容出处”“实验支持”“假设来源”等实际作用，不新增固定语义分类。
6. 无法提供可靠位置的候选内容进入 gaps，不能作为已证据锚定的正式节点发布。

### 4.6 可选分组与材料缺口

groups 建议含 groupId、title、nodeIds，可附 description。分组是语义组织信息，不生成学术连线，不增加第三层。节点可以属于多个有意义的分组；有重叠时用标签／筛选表达，不强迫节点重复出现在多个实体容器。

gaps 建议含 description、relatedNodeIds、relatedEdgeIds、suggestedPages；后面三个字段可为空。页面建议只是定位线索，不等于已读到的证据。

- 未连通本身不等于缺口。
- 没有某种节点角色不等于缺口。
- 所有 gaps 都应说明具体缺少什么材料或哪条关系尚无法核实。
- 不以“未引用多少 OCR 块”作为主要质量结论。

### 4.7 完整示意

以下是虚构材料示意，仅说明数据形状，不得作为所有论文的结构模板：

## 5. 生成流程、上下文与计划冻结

### 5.1 总图流程

~~~text
打开地图
  → 本地计划：校验依赖、冻结输入、展示调用估计
  → 用户开始
  → 复用／按已有流程建立 PDF-only 来源根
  → 整体构图：联合生成节点与关系
  → 保存原始响应和收据
  → 本地结构／定位校验；必要时使用一次共享修复额度
  → 检查与定稿：独立对照原文复核候选图
  → 保存原始响应和收据
  → 本地结构／定位校验；尚有额度时可修复
  → 发布前检查依赖、取消、父版本／期望 head
  → 事务发布
~~~

正常总图调用为两次；结构修复额度整个总图任务最多一次，而不是每个阶段各一次。第一次耗尽修复后，第二阶段仍无效则保留恢复材料，不继续自动付费。

检查与定稿是必经的内容阶段，不因候选图 JSON 合法而跳过。其目标是交付最终图，不强制必须找到问题或改动若干节点。

### 5.2 来源根与分支

- 新路径使用已有 PDF-only 来源根接口，例如 ReadingArtifactModule 的 ensure_root_for_route／lookup_root_for_route_with_instruction。
- 按文档、PDF 摘要、精确 route、model、来源根协议与根提示词身份复用。
- 来源根只承担原始文档缓存，不加入地图、读者笔记或其他派生成果。
- 构图、复核和局部图从来源根各自分支。复核显式收到 candidateGraph，不通过继承构图会话获得候选内容。
- 来源根缓存复用不意味着每次生成调用免费；调用估计必须分别展示。
- 不读不写 Discussion，不借用旁批 memo。
- v4 默认不调用 orientation_context。未来若增加用户主动携带辅助成果，必须标注其派生性质并冻结内容，不能静默恢复自动注入。
- 本期默认也不注入 Reader 上下文，保持地图为文档本身的稳定结构成果。未来调整属于新的产品决策。

必须检查 adapter 的真实请求链，不能仅凭 previous_interaction_id 为空就声称获得了来源根隔离。

### 5.3 OCR 与原生 PDF 的分工

- 原生 PDF 是理解原文的来源，OCR 目录主要是定位白名单。
- 约 80 字 excerpt 可以继续作为定位线索，提示词必须说明它不是全文。
- 不把稀疏 OCR 或短 excerpt 冒充读过完整论文。
- 原生 PDF 能力、页数、体积、加密及输入窗口检查沿用项目已有能力。
- 输入预算同时计算系统稿、原生 PDF 估计、目录、候选图、复核指令及输出预留。
- 每次调用前用实际材料重新预检；估计不能当成准确 token 计数。
- 超窗口时停止并给出切换合适模型或选择明确范围的入口，不静默截掉中间页、附录、候选节点或关系。
- 若只有检查阶段因为候选图过大而超窗口，保留候选图和已付费结果，标明复核未完成。切换模型是新计划，不能修改在途任务的冻结路由。

### 5.4 冻结计划

计划阶段不调用模型。建议冻结：

- documentRevisionId、PDF hash、OCR revision、catalog 及 digest、文档类型。
- scope：全文或用户明确选择的范围；本期不新增隐式范围推断。
- 来源根提示词、整体构图提示词、检查提示词；局部计划冻结局部稿。
- 提示词协议元数据及内容摘要、输出语言。
- 精确 provider route、模型、输入限制、已有路由凭据引用；不得保存密钥明文。
- 预计调用次数、共享修复预算与已知能力。
- expectedHeadId、planId、planDigest、publishId。
- 局部计划额外冻结 overviewRevisionId、nodeId、节点内容、邻接关系、目录和范围。

开始时验证计划仍匹配当前用户选择；不匹配时重新展示计划，而非重新读取新参数后执行旧确认。

缓存命中情况只影响调用估计，不把缓存恰好消失误判为文档内容改变；根失效后按现有显式恢复规则处理，不偷偷超过确认预算。

本次计划的“冻结”仅针对调用输入；候选节点和关系在模型构图及复核阶段仍可调整。

### 5.5 防重复与进度

- 同一文档修订的互斥操作在统一入口检查；切换 provider 不能绕过防重复。
- 同一计划重复开始返回同一任务，不重复入队。
- 新进度显示“整体构图 → 检查与定稿 → 保存地图”；修复作为该阶段的子状态。
- v3 任务仍显示“抽单元 → 构图”。
- 无需将协议 ID、内部 checkpoint 或模型推理细节放进正常阅读界面。

## 6. 持久化、恢复与发布

### 6.1 每个逻辑调用单独记账

建议逻辑槽：draft、draft_repair、review、review_repair；其中 repair 只能有一个实际消耗。局部图使用 local、local_repair。

每个槽至少记录请求摘要、in-flight 状态、响应原文、provider node、usage／receipt、解析状态及错误。

- 发请求前保存 in-flight。
- 收到响应后，先保存原始结果与收据，再解析和进行取消后的发布判断。
- 解析失败不丢弃付费结果。
- 恢复优先重放保存的响应，不重新发送。
- 结果未知时进入现有 interrupted_unknown 流程，不自动补发。
- 收据按任务、逻辑槽、route 幂等写入；来源根收据遵循其原有记录机制，避免重复计算。
- 可参考 guide_generation 的 call_once 及 guide_runtime 的收据模式；先审查其适用性。地图代码不应依赖旁批领域模块；仅在必要时抽出小型共用调用记录模块，避免顺手重构所有功能。

### 6.2 状态与可见性

| 情况 | 持久化与显示 | 是否移动正式 head |
| --- | --- | --- |
| 候选图生成且有效，尚未复核 | 保存候选；用户主动查看时明确“未完成检查” | 否 |
| 复核失败／超预算／取消 | 保存已收到结果，显示阶段与恢复入口 | 否 |
| 复核完成、结构有效、无具体缺口 | 正式地图 | 是 |
| 复核完成、结构有效、有明确材料缺口 | 正式可用图附“存在材料缺口”提示 | 是 |
| 图完全无有效节点 | 无有效地图；保留失败信息 | 否 |
| 布局出错 | 同一有效图退回节点／关系列表 | 不改变数据 head |

复核完成不等于科学正确性已被证明。界面用“已完成检查”，不使用“已证实正确”。

建议分开表示 generation／review 状态与 content gaps。不要复用一个含义不清的 partial 同时表示“没审完”和“审完但有缺口”。

第一次生成未完成时可以显示经过定位校验的候选节点列表；其标题和状态须明确，不能把它包装成正式图。

### 6.3 原子发布与版本竞争

- 正式 revision、head 和发布完成标记在同一事务写入。
- publishId 在计划／入队时生成，恢复后保持不变。
- 发布使用 expectedHeadId；期间出现新的 head、删除或依赖变化时，旧任务不得覆盖新状态。
- 局部发布要求父 overviewRevisionId 仍满足对应生成条件，不得接到同名的新节点上。
- OCR／PDF 改变、文档删除或取消须在发布前重新检查。
- 工作区切换后，任务仅使用已捕获的 Arc<WorkspaceRuntime>，不能从新的 current_runtime 取模块继续写入。
- 已完成发布的旧任务再次恢复也不能覆盖后来生成的 head；幂等记录不能只依赖可能已被删除的 revision 行。
- 成功重生成后的旧版清理沿用明确的产品保留策略；迁移阶段保留旧图与旧局部图。失败尝试绝不触发旧成果清理。
- 取消、删除与 head 竞争至少用故障注入／并发测试覆盖。

## 7. 三类提示词与六份中文稿

### 7.1 文件与存储

建议新增运行时文件：

| 槽位 ID | V4 显示名称 | 运行时文件 |
| --- | --- | --- |
| outline_extract | 整体构图 | src-tauri/prompts/outline-draft.paper.md、outline-draft.textbook.md |
| outline_compose | 检查与定稿 | src-tauri/prompts/outline-review.paper.md、outline-review.textbook.md |
| outline_deep_dive | 局部展开 | src-tauri/prompts/outline-deep-dive.paper.md、outline-deep-dive.textbook.md |

完整定稿放入 docs/note/outline-prompts.md，并与六份运行时文件做一致性校验。该路径是计划中的新文件，不是当前已存在的成果。

保留物理槽 ID 是为了兼容存储／IPC，不代表沿用旧语义；设置页和任务进度根据协议显示名称。

### 7.2 共用写作结构

每份稿至少包含：

1. 任务目标与完成后读者能理解什么。
2. 实际可见材料及其权威层次。
3. 开放的结构设计原则。
4. 本阶段特有职责。
5. 字段含义与引用规则。
6. 不确定性、材料缺口和输出前检查。
7. JSON、Markdown／LaTeX 转义约定。

避免：

- 固定节点数、固定角色配额、固定关系词表。
- 按论文类型强制填齐预设章节模板。
- 要求单链、连通、无环或每页都被引用。
- 要求输出逐步内心推理。
- 把示例列成穷尽选项，或要求复核必须改动一定数量的内容。
- 省略此前已讨论清楚的具体规则，只保留几句抽象概括。

### 7.3 整体构图：论文稿

职责：

- 从全文识别最能体现本文贡献、论证或发现的结构。
- 同时考虑节点与关系，允许在生成过程中重选粒度。
- 识别必要的问题背景、设计、前提、发现、证据和边界，但不要求每篇论文都有这些类别。
- 对方法、理论、实证、综述及混合型论文采用实际适合的结构；类型例子仅作启发。
- 保留并行证据、不同观点、竞争解释和独立发现。
- 标题表达具体内容；takeaway 保留决定含义的条件；关系标签具体、方向明确。
- 来源不足的内容形成具体 gaps，不用常识填补为论文主张。

### 7.4 整体构图：教材稿

职责：

- 识别该份材料实际包含的概念、依赖、推导、性质、程序及应用联系。
- 可以围绕问题、概念体系、求解过程或几个相对独立的主题构图。
- 例子与习题只有在帮助理解结构时才成为节点，不逐题铺满总图。
- 不自动扩写课外知识、不安排完整课程、不把学习顺序强加为所有关系。
- 输入 scope 是整本时不能默认声称只读“本章”；输入 scope 是章节时不越界编造整本结构。

### 7.5 检查与定稿：论文稿

职责：

- 候选图是待核查的模型输出，原文仍为依据。
- 独立检查内容遗漏、重复、粒度、引文匹配及关系是否夸大。
- 检查作者主张与观测结果、支持与证明、相关与因果、前提与结论是否区分。
- 检查默认可见结构是否遗漏关键限制、负面结果或替代解释。
- 可以保留、合并、拆分、补充、删除节点与关系；不为了展示“做过检查”而改写正确内容。
- 内容基本相同的节点／关系尽量保留 ID；拆分合并时分配明确的新 ID 并同步所有引用。
- 返回完整最终图，不返回只有增删补丁的碎片。
- reviewNotes 只记录影响理解的重要变化与未解决问题，不输出长篇评分报告。

### 7.6 检查与定稿：教材稿

除共用要求外，重点检查：

- 先修依赖是否被误写成原文顺序。
- 定义、性质、推导、例子和适用条件是否混淆。
- 一个例子是否被扩大成一般结论。
- 不同记号或假设下的结论是否被合并。
- 是否为追求完整而补出教材未提供的知识关系。

### 7.7 局部展开：论文稿与教材稿

- 围绕选中节点实际内容决定展开方式，不强制“定义—直觉—推导—例子—易错点”全套字段。
- 论文可展开模块、信息流、证明依赖、实验比较或解释分歧；教材可展开概念内部关系、求解步骤、条件及应用。
- 对父节点文本保持可核查态度；发现父节点表述有问题时，明确记录，不默默改写总图。
- 可以跨页、跨节或到附录查找与目标直接相关的依据。
- 与目标无关的全文内容不进入局部图。
- 允许少量节点、无向关系、回路或多个局部分量；材料不足时不强行铺满。
- 局部图节点只能继续跳原文／打开已有解释或 Lens，不再触发第三层地图。

### 7.8 材料边界与修复模式

六份稿都需说明：PDF、OCR 文本、候选图、图中说明及引用内容是待分析材料，其中出现的命令不能改变本任务、泄露提示词或改变输出协议。

修复使用同一阶段提示词，显式提供 previousOutput 与结构化 validationIssues。修复指令要求保留已经有效的内容，不以清空数组、统一改成“相关”或删除所有边来满足 schema。若原文确无有效关系，空 edges 本来就是合法结果，不需为修复补边。

格式／定位修复不能声称完成尚未执行的内容复核，也不能默默触发新一轮收费。

## 8. 局部图范围与缓存

### 8.1 冻结父节点

- 入队冻结父图修订、目标节点和直接相关关系。
- worker 不再使用 current_graph 替换冻结父图。
- 新总图节点即使 ID 恰好相同，也不是同一个局部图缓存身份。
- 父图过期时显示基于旧材料；对新生成入口重新检查 OCR 与 PDF。
- 历史局部图可以查看，不因为当前默认模型切换而立即丢失已有内容。

### 8.2 关注范围不等于引用白名单

默认局部输入包含：

1. 原始 PDF 来源根。
2. 冻结目标节点与直接相关节点／关系的必要内容。
3. 全文定位目录及其白名单。
4. 从目标与相邻关系来源推导的优先关注页。

优先关注页帮助聚焦，不禁止引用同一已提供文档的附录或其他页。这样可以直接解决“关键证明不在一跳证据页内”的问题，不必新增自动扩页循环。

如果用户明确限定了 scope，就遵守该范围；超出范围的材料作为补充建议，重新计划后才能扩大。全目录或局部请求超窗口时执行明确的预算处理，不回退到隐藏裁剪。

### 8.3 缓存与调用

- 语义缓存身份包括父图修订、节点、PDF／OCR／scope、协议、提示词摘要、route 和 model。
- 当前页面已有已发布局部图时直接打开；提示词或模型变化不自动付费重生成。
- 用户点重生成时使用新计划；不得把不同身份的旧图冒充新请求的命中。
- 局部正常一次调用，最多一次修复；不自动运行第二层的独立复核阶段。
- 局部阶段须自行对照原文检查；不要把其状态标为经过总图同样的“两阶段复核”。

## 9. 画布、布局与交互

### 9.1 语义图与布局图分离

持久化语义图完整保存自由关系。布局只计算坐标与路径，不改节点内容、关系方向和含义。

建议在现有 dagre 基础上增加适配层：

1. 计算包含有向与无向联系的弱连通分量。
2. 每个分量中，对有向边计算强连通分量，将其收缩为布局用 DAG。
3. 在收缩图上进行分层；在强连通分量内部安排成员并绘制回路。
4. 无向边用于邻近／分量组织与显示，不伪造学术箭头；仅由无向边连接的组件可以采用稳定网格或径向安排。
5. 排布多个独立分量，保留可辨认间距。
6. 恢复全部真实边，给平行边、反向边、自环分配不重合的曲线。
7. 如需虚拟根或辅助布局边，只存在于布局内存，不进入模型结果、持久化图、关系详情或导出。

允许采用更简单但等价的实现，前提是多分量、反馈、无向边、平行边与方向保真通过测试。第一期不预设引入新布局依赖；确需替换时记录收益、成本和回退行为。

### 9.2 显示原则

- 节点卡：具体标题，可选角色；takeaway 在详情中完整显示。
- 角色没有预设颜色时使用默认样式，不显示 other 或未知角色错误。
- 默认保留全部有效节点与关系，包括限制和反向证据。
- 标签可以在低缩放时简化显示，但关系本身与隐藏文字的可发现性须保留。
- 焦点模式只在用户主动选择后显示邻接子图，界面说明当前有过滤并提供恢复全图。
- 不默认把自由关系再映射成 narrative／cross_link 后隐藏一部分。
- 去掉“阅读序号”暗示；如保留编号，应明确为节点编号，不表示先读顺序。
- 分组标签、搜索、筛选不修改语义图；复杂分组容器不是首期阻塞项。

### 9.3 连线详情

新增与节点详情共用面板的“关系详情”：

- 起点标题、关系标签、终点标题及方向。
- rationale 和 uncertainty。
- 引用位置与 purpose。
- 点击引用跳 PDF 对应 block／物理页。
- 点连线不自动跳 PDF。
- 键盘能够聚焦、选择关系和关闭面板；标签只靠 hover 不算完成。
- 节点与连线选择使用明确的状态类型，避免同时选中两个对象。
- Esc 一次只执行当前层级关闭动作，不能同时退出 Reader。

### 9.4 降级

布局异常或可读性不足时，提供同一语义图的节点／关系列表：

- 不删除有环或不连通的数据。
- 列表包含连线说明与引用。
- ErrorBoundary 限制故障范围，不让整个 Reader 空白。
- 大图优先通过缩放、搜索、聚焦和列表处理；性能预算不能伪装成学术节点上限。
- 遵循现有懒加载、PDF 常驻、面板宽度与布局状态持久化合同。

## 10. 旧成果、旧任务与自定义提示词迁移

### 10.1 迁移总原则

本次升级不得因协议变化删除旧地图、局部图、任务、提示词或恢复历史。

- 不通过把 OUTLINE_EPOCH 从 3 改成 4 来执行破坏性清空。
- 审查所有打开数据库／读取提示词时触发的历史迁移，避免新迁移进入旧删除分支。
- 对更早且已不支持的协议保留原始记录并显示兼容状态；不得静默按 v4 解释或扩大历史清理范围。
- 对当前已支持的 v3 图保持可读，不伪造已完成 v4 复核的标识。

### 10.2 旧图投影

- 后端／前端按 protocolVersion 区分 v3 和 v4。
- 可用适配器向画布提供共同的显示结构，但原始存储保持原样。
- v3 roleLabel、label 存在时优先保留；缺少时可用历史枚举的中文显示文本，标明旧版来源。
- v3 节点 confidence 不转换成新版本的“真实性概率”。
- v3 固定 tier 仅用于旧版兼容，不进入 v4 生成 schema。
- v3 → v4 是用户发起的新生成，不是本地改写元数据。

### 10.3 提示词按完整 bundle 管理协议来源

为每种文档类型保存三个槽及各自 current／previous 的协议身份。论文和教材的 bundle 独立。

- 全套为可识别的旧出厂稿：备份当前及历史后，升级至六份相应新默认。
- 存在用户自定义旧稿：整套继续保留 v3，可继续原有流程；提供明确的整套升级入口。
- 不在“旧抽单元稿＋新审稿 schema”之类混合组合下执行。
- 恢复上一份必须同步恢复文本与协议来源。
- 在旧稿上编辑仍是旧稿协议；不能仅凭文本不同于默认就自动标为 v4。
- 用户选择“使用新版整套默认”才切换该文档类型 bundle；用户也可以在了解字段合同后主动将自己的整套稿适配至 v4。
- 若逐槽恢复造成混合协议，保存草稿可以保留，但生成前须明确阻止并说明需要统一；不能默默替换另外两个槽。
- 设置页说明当前运行的是“旧版抽取流程”还是“新版整体构图流程”。

迁移应幂等，失败不得只写一半。新旧 current、previous、自定义内容都需要回归测试。

### 10.4 旧任务

- 旧任务继续使用已冻结旧提示词、旧 schema、旧校验器和旧阶段。
- 不能恢复到一半后把 units 当作 candidateGraph。
- 缺少新路径必要快照的新任务，在任何付费前明确要求重新计划。
- 支持未来版本的拒绝策略，不能按最新默认兜底。
- 保留旧任务的 usage、恢复和人工确认语义。

### 10.5 其他消费者

搜索所有读取 Outline 图、units、角色或边的地方，包括旁批旧路径、成果索引、删除预览、导出、诊断、mock 和测试夹具。

- 当前旁批 V2 已有独立 memo，不应为了兼容地图重新绑定旁批。
- 旧消费者只能通过明确的兼容投影读取，不能把 v4 空 units 误判为无成果。
- 若数据库 units_json 仍有非空列约束，v4 可写合法空数组并以 graph 为权威，不反向生成冗余固定单元。
- 新接口与 DesktopClient mock 同步更新，避免生产已改而预览仍展示旧流程。

## 13. 验收矩阵

### 13.1 语义自由与数据正确性

| 用例 | 预期 |
| --- | --- |
| 模型返回“揭示了两种定义的差别”等新关系 | 原样保存，不归入 other |
| 模型返回“识别策略”等新节点角色 | 正常显示 |
| 无 roleLabel | 正常显示 |
| 单节点、零边 | 合法 |
| 多节点、零边或多个独立组 | 合法，不自动补边 |
| A→B→C→A 且有依据 | 保留回路并可显示 |
| 有依据的自环 | 保留并可查看 |
| 无向比较 | 不伪造方向 |
| 同端点存在两条不同关系 | 两条均可见可选 |
| 缺少某一预设论文角色 | 不触发错误或补齐 |
| 大图 | 不因超过学术节点配额失败；资源问题明确报告 |
| 不存在的端点、重复 ID | 明确结构错误，进入有界修复 |
| 目录外 block、页码越界、页块冲突 | 明确定位错误 |
| 合法页级定位 | 显示页级提示并正确跳转 |
| 模型合并或拆分候选节点 | 最终关系与分组全部引用有效 |
| 内容归纳但原文未直接表述 | rationale 说明归纳，引用足以核对 |
| 图有关键限制或反向证据 | 默认视图可见 |
| 持久化结果重新打开 | ID、关系和引用不漂移 |

### 13.2 流水线、预算与恢复

| 用例 | 预期 |
| --- | --- |
| 正常总图 | 一次构图＋一次复核 |
| 构图结构错一次 | 使用共享修复额度，随后复核 |
| 构图已修复，复核仍结构错 | 不再自动修复，不超预算 |
| 构图无问题、复核输出结构错 | 最多一次 review 修复 |
| 结构合法但复核调整了结论边界 | 保存完整修订图 |
| 复核未改变正确候选 | 合法，不要求制造改动 |
| 复核超窗口 | 保留候选、费用和恢复信息，不裁剪 |
| 收到响应后解析崩溃 | 恢复重放该响应，不重新请求 |
| 收到响应后取消 | 保存结果与费用，不发布 |
| 请求结果未知后重启 | 不自动补发 |
| 发布完成后旧任务再次恢复 | 不覆盖更新的 head |
| 计划后换模型／提示词／OCR／scope | 旧计划不能继续消费新输入 |
| 来源根命中 | 不把 Brief／Discussion／上一张地图带入请求 |
| 缓存失效 | 不悄悄超过确认开销 |
| 工作区切换 | 旧任务只操作已捕获运行时 |
| 并发开始或切换 route 重复开始 | 不产生重复生成 |
| 复核失败时已有旧正式图 | 旧图保留，最新尝试单独显示 |

### 13.3 局部图、迁移与 UI

| 用例 | 预期 |
| --- | --- |
| 证明在附录 | 全文范围内可准确引用 |
| 显式局部 scope 缺材料 | 报告缺口，不自行扩大范围 |
| 父图生成新版本 | 在途旧局部图不挂到新节点 |
| 点击已缓存局部图 | 不调用模型 |
| 未点击生成局部图 | 不自动预生成 |
| 点击局部图节点 | 跳原文／Lens，无第三层生成 |
| v3 成果升级应用 | 保留可读 |
| v3 自定义稿＋恢复历史 | 文本与协议来源保留 |
| 一套提示词混合 v3／v4 | 生成前明确拦住，不偷偷改稿 |
| 未知未来协议 | 付费前拒绝 |
| 点击节点／连线 | 只打开相应详情 |
| 点击引用 | 正确 block／物理页定位 |
| 键盘选边与 Esc | 可操作且不误退出 Reader |
| 标签遮挡或缩放 | 完整文字和关系仍可找到 |
| 布局异常 | 同图列表可读，Reader 不空白 |
| v4 无 units | 成果索引和兼容消费者不误判为空 |

### 13.4 内容验收样本

至少覆盖以下内容类型；数量只用于测试覆盖，不是生成约束：

- 方法论文：包含并列模块和消融证据。
- 理论论文：依赖假设、多个引理及附录证明。
- 实证论文：存在解释边界，不能把相关写成因果。
- 综述：多个流派、共同认识与未解决分歧。
- 具有负面结果或独立发现的论文。
- 教材概念章与推导章／算法章。
- 图表密集、OCR 不完整但 PDF 可读的材料。
- 合理的单链、多分量与反馈结构。

人工记录：核心内容是否遗漏、节点是否重复、关系是否成立、条件是否保留、引用能否核对、总图／局部图是否分工清楚。记录具体错误和原文位置，不能只写“效果很好”。
