### 任务定位、收录范围与基本深度：已确认（2026-09-08）

```text
请依据提供的完整 PDF，整理帮助读者理解本文或本章的符号表。

目标是让读者在遇到一个符号时，能够查明它表示什么对象，
在文档中承担什么作用，以及这一含义适用于哪些位置或条件。

默认读者具备一般学术阅读能力，但不假设熟悉本领域的符号惯例。
说明使用中文，符号保留原文写法及影响含义的形式差异。

收录理解文档中的问题、方法、论证、实验和结果所需的变量、
参数、常数、集合、函数、算子及具有专门含义的上下标或其他记号。

同时考虑全文反复使用的符号与局部使用的重要符号。
即使只出现一次，只要影响对关键公式、推导、图表或算法的理解，
也应收录。不要仅根据出现频率或是否进入 Brief 决定取舍。

阅读范围包括正文、公式、图表、脚注和附录。
参考文献条目或被引用材料中偶然出现、且未被本文使用的符号，
不因此单独收录。

对于加减、等号、括号等通用记号，仅在本文赋予特殊含义、
采用特殊约定，或其用法确实影响理解时收录。
收录数量随文档需要调整，不设固定条数，也不靠重复条目凑数。

解释应具体到本文中的对象与用途，不能只写“一个参数”
“一个函数”或“某个集合”。补充识别该符号所需的背景，

如实说明，不凭惯例补成作者的定义，也不借助其他生成成果补齐。
```

### symbol：已确认（2026-09-08）

```text
symbol：记录本条目对应的原文符号，使用标准 LaTeX 表达，
不添加数学定界符、中文名称或解释性文字。

保留影响含义的大小写、正体与斜体、粗体、花体、黑板粗体、
上下标、重音及其他修饰。不要为了统一外观，将不同符号
改写成同一个普通字母，也不根据领域惯例擅自修改原文写法。

不同写法表示不同对象或承担不同作用时，分别收录。
例如，原文用 x 表示标量、\mathbf{x} 表示向量时，应予以区分；
估计量、最优解、归一化量等带有专门修饰的符号，也应保留
使其区别于原量的写法。

同一符号在不同位置表示相同对象、具有相同含义时，原则上
合并为一个条目，在 scope 中交代适用范围，不因重复出现
或分页而建立重复条目。仅有排版间距或括号尺寸差异的写法，
不因此分别收录。

对于仅索引取值不同、含义遵循同一规则的一组符号，优先使用
原文已有的通用形式归并，例如 x_i，并在 meaning 中说明
索引的含义及必要范围，不逐个枚举 x_1、x_2 等实例。
没有可依据的通用形式时，保留原文实际使用的记号。

若特定上下标或修饰表示不同角色、状态、阶段或专门定义的量，
应按其实际含义区分，不把有实质差异的符号机械归并成一族。
每个条目对应一个可明确解释的符号或符号族，不把多个无关
符号并列堆入同一个 symbol。

函数或算子的写法应保留辨认其含义所必需的参数、上下标
和修饰；不要把整行等式、推导或定义说明放入 symbol。
必要的定义公式在 meaning 中解释。

同一个符号在不同章节、公式或条件下具有不同含义时，
按含义分别建立条目，允许这些条目的 symbol 完全相同。
分别用 meaning 和 scope 说明各自的含义与适用范围，
不要为了区分条目，在 symbol 中添加原文不存在的下标、
章节标签或中文括注。
```

### meaning：已确认（2026-09-08）

```text
meaning：用中文解释该符号在本文中表示的具体对象、数学或
物理含义，以及它在相关方法、论证或计算中的作用。
让读者能够带着这段解释返回原文，理解含有该符号的表达式。

先说明它具体指什么，再按理解需要补充对象类型和用途。
例如，说明向量包含什么信息、矩阵描述什么关系、参数控制
哪一部分，而不止写“一个向量”“一个矩阵”或“模型参数”。
不要仅根据字母、字体或常见惯例推定对象类型。

当这些信息影响理解时，交代必要的维度或形状、单位、
定义域、值域、取值约束及归一化约定。
只写原文能够支持的信息，不要求每个条目机械填齐这些项目。
区分对象的一般定义与特定实验、数据集或设置中的具体取值，
不把局部设置写成该符号始终具有的性质。

对带索引、上下标或其他修饰的符号，解释这些部分的具体
含义，例如它们区分的是样本、分量、时间、层次还是迭代步骤。
必要时交代索引范围，以及修饰后的量与原量之间的关系。
帽号、星号等修饰按本文定义解释，不默认其一定表示估计值
或最优解。

对函数，说明必要的输入、输出及其对应关系；对算子，说明
它作用于什么对象、执行什么运算；对概率、分布或期望，
说明相关随机对象，以及影响含义的条件或所依据的分布。
根据符号的实际类型选择需要解释的内容，不套用统一模板。

必要时保留简短的原文定义公式或关系式，并用自然语言说明
其含义及其中不可缺少的量。不能只抄公式而不给解释，也不
展开与辨认该符号无关的完整推导。仅用到的近似关系、特殊
条件下的等式或作者假设，应保留相应限定，不改写为普遍定义。

区分作者明确给出的定义与依据上下文作出的推断。
需要推断时，明确标示并简要交代所依据的公式、描述或用法。
仍无法确定的部分如实说明，保留已经能够确认的含义；
不因某项信息缺失而否定整个条目，也不凭常识补齐作者未给出
的具体维度、单位、约束或性质。只指出影响理解的缺口，
不对每个条目机械罗列原文未说明的项目。

每条解释应能独立理解，避免仅写“同上”或只转引另一个条目。
引用其他符号时，补足理解当前条目所需的最少说明；专业概念
按需简释，不在这里重复整份术语表。

保留构成定义或直接影响用法的条件。符号含义的适用范围在
scope 中说明，支持该解释的原文出处在 sources 中记录。
各字段相互配合，避免重复堆砌定位信息。

解释长度随符号复杂度调整。简单符号简洁说明，复杂符号
```

### scope：已确认（2026-09-08）

```text
scope：用中文说明本条目所解释的符号含义，在文档的哪些
部分、讨论对象、模型设置或使用条件下适用。
让读者能够判断，当前遇到的符号是否应按本条目的 meaning 理解。

区分全文或全章沿用的约定与局部定义。
只有原文明示为通用约定，或相关用法足以支持这一判断时，
才表述为“全文适用”或“本章通用”。不因符号首次出现较早、
出现次数较多，或没有找到明确的重定义声明，就默认其全文同义。

对于局部定义，说明能够辨认其范围的章节、定理、证明、
公式组、图表、算法、实验设置或讨论场景。
引用这些名称或编号时，应以原文可确认的信息为依据。
不把首次定义的位置直接当作整个适用范围，也不把只在某处
观察到该用法，写成它只能用于该处。

当符号的含义或使用方式取决于特定模型、近似、边界条件、
训练或推断阶段等因素时，保留足以区分条目的条件。
构成符号定义的具体约束在 meaning 中解释；scope 说明
该定义适用的场景，避免机械重复整个定义。

同一符号存在多个含义时，各条目的 scope 应提供能够区分
这些用法的信息。若不同含义出现在同一章、同一节甚至同一页，
继续用具体公式、论证对象、算法阶段或其他可确认的场景区分，
不能只给出相同而宽泛的章节名称。

同一含义适用于多个不连续部分时，可以合并说明这些范围；
若存在原文明示或实际用法能够确认的例外，应说明例外。
不要为了让范围看起来连续，将未经确认的中间部分一并纳入。

适用范围应尽量准确、简洁，不逐次罗列符号的全部出现位置。
支持定义或解释的具体原文出处在 sources 中记录；章节或
公式编号在有助于划清适用范围时，也可以出现在 scope 中。

对只能由上下文推断的适用范围，明确标示推断性质。
范围不明确时，说明能够确认的使用场景与尚不能确定的边界；
确实无法辨明时，写明“适用范围未能从原文确定”，不猜造
章节区间、页码范围或全局约定。
```

### sources：已确认（2026-09-08）

```text
优先选择直接定义该符号的位置，以及解释其含义、约束或

不要仅因某处出现相同符号，就将其作为当前解释的依据；
尤其要核对该处是否属于同一含义和适用范围。

出处数量随证据需要调整，不设固定条数，不收集全部出现位置。
同一出处能够支持多项必要信息时可以合并说明。
如果一项判断需要结合多处材料，应记录必要出处，并说明
它们如何共同支持判断，不把其中任意一处写成充分依据。

supports 用中文说明该出处支持了当前条目的哪部分解释。
```

```text
核心关系，并解释关键符号、量之间的关系及公式承担的作用。
不能只抄公式而不给自然语言解释，也不为显得严谨堆积公式。
仅当必要的简短推导能够澄清核心含义时才展开；不在术语表
中复现与理解该概念无关的完整证明或算法细节。

抽象概念仅靠定义仍难以理解时，可以给出简短例子、反例
或类比，说明它具体体现了哪项特征或区别。
自行构造的例子应明确是帮助理解的示例，不作为本文的实验、
数据或结论；类比有可能误导时说明其适用限度。
例子服务于概念解释，不替代定义，也不要求每个条目都配例子。

与相近概念的比较，只在有助于避免实际混淆时加入。
具体指出区别发生在哪个对象、条件、机制或判断标准上，
不泛泛罗列相关术语，不将有关联或部分重叠写成完全同义。

每条解释应能独立理解。使用影响理解的前置概念时，补充
必要的简短说明；可以联系其他条目，但不能只写“见某词条”
或“同上”。背景展开到足以理解当前概念即可，不递归扩写
成完整课程或与本文阅读关系松散的知识综述。

原文或可靠背景不足以确定含义时，保留能够确认的内容，
说明具体缺口或歧义。依据上下文推断的部分应明确标示，
不能用流畅、确定的表述掩盖尚未建立的关系。
不为每个条目机械附加不确定性声明。

本文的具体应用对象、实验设置、局部角色和使用范围在
usage 中说明；支持原文定义或推断的出处在 sources 中记录。
构成概念定义的条件仍应在 definition 中保留，各字段按
职责配合，避免重复整段内容。

解释深度随概念复杂度和理解需要调整。
简单概念简洁说明，关键或抽象概念展开到足以理解核心含义、
必要条件与重要区别，不设固定句数，也不以篇幅长短代替解释质量。
```

### relatedVersions：已确认（2026-09-08）

建议 relatedVersions 为数组，每项恰含 relativeTo、relations、target。增加 relativeTo，用于区分当前文档自身的另一版本与直接所属出版物的另一版本，避免将章节 PDF 中的整书版次关系误归给章节。target 是关联版本的部分书目记录，不要求补齐一份完整 document。

|---|---|---|
| relativeTo | document / container | 关系参照的当前对象；container 必须已经能够确认 |
| relations | 非空数组 | 每项包含 type、relationText；同一关联版本可同时有多个有依据的关系 |

```text
对应当前文档直接所属的出版物。例如，章节 PDF 提到整书
的另一版时，应关联 container，不能把整书的版本信息
写成该章节自身的另一版本。
只有相应参照对象及其归属能够确认时才建立记录；container
为 null 或关系归属不明时，在 issues 中保留线索与问题，
不任意选择参照对象，也不将同一关系同时复制到两处。

relations 为非空数组，每项包含 type 和 relationText。
所有关系类型都描述 target 相对于 relativeTo 指定对象
的关系，不能在不同条目中交换方向。
earlier_version 表示 target 是该对象的较早版本；
later_version 表示 target 是该对象的较晚版本；
translation 表示 target 是该对象的译本；
translation_source 表示 target 是该对象翻译所依据的
原文版本，不自动意味着它是作品最早的版本；
other 表示原文明确的其他版本关系；
unknown 表示版本关联本身已经确认，但具体关系类型
无法可靠确定。尚不能确认是否存在版本关联时，不使用
unknown 把疑似相关作品纳入数组。

同一关联版本可以同时满足多个关系，例如既是较早版本，
也是当前译本所依据的原文版本。此时在同一条目的 relations
中分别记录有依据的关系，不为每种关系复制一份 target。
同一参照对象下互相矛盾的关系，先核对版本和原文语境，
不能用同时填写 earlier_version 和 later_version 的方式
代替对冲突的处理。

relationText 保留原文明确表达该关系的简短句子或短语，
保留必要的方向、否定与限定，不改写为模型生成的关系说明。
需要结合分散位置才能确认关系、没有可忠实单独摘录的
表述时，可以使用 null，并在 sources 中分别关联依据、
解释判断过程，不拼接出原文不存在的连续引文。
other 的具体关系和 unknown 的不确定之处也应有可核对的
说明与依据，不能只留下无法理解的类型标签。

先确认版本关联，再判断先后、翻译方向或其他具体关系。
标题相近、作者重合、内容相似或年份不同，都不能单独证明
两个对象是同一作品的不同版本。参考文献中出现同名作品，
也不自动构成版本关系。
原文明示早期稿、修订版、译本来源或正式发表的对应版本等
关系时，可以记录；只说明借鉴、扩展研究方向、相关工作、
补充材料或勘误时，不能自动当作另一版本。

预印本、接收稿、正式发表版等身份描述放入 target 的
versionInfo，保留原文能够确认的标签。
关系类型不能代替这些身份描述，也不根据通常的出版流程
自动补齐先后关系。只确认存在对应发表版本而无法确认版本
先后时，可以使用 other 并保留原文关系表述，不为了填写
later_version 而推断发布日期或内容先后。
拟投稿、计划修订或未来将推出某版的表述，不能写成该版本
已经存在或已经发表；需要保留的计划性线索放入 issues，
明确其实际状态。

target 记录关联版本本身，包含 title、alternateTitles、
contributors、versionInfo、dates、identifiers 和 container；
出版者信息按后续字段规则补充。
前六项沿用已经确定的题名、贡献者、版本、日期和标识符
结构与保真规则。这里不要求填写一份完整的当前文档记录，
也不把当前 PDF 的 coverage 用作未读取版本的完整程度。

target.container 表示关联版本自身所属的出版物及书目
位置，沿用已确定的 container 与 placement 规则。
例如，当前预印本中注明对应发表版本的期刊、卷期、页码和
DOI 时，期刊与刊载位置属于 target.container，文章 DOI
属于 target.identifiers；先核对原文归属，再分别记录。
relativeTo 为 container 时，target 代表的是该所属出版物
的另一版本，target.container 也只能表达这个版本自身的
所属关系，不能把当前章节的位置复制进去。

关联版本可以只保留部分信息。
原文只给出对应版本的 DOI、题名、版本标记或发表位置时，
保留这些内容，其余按各字段规则使用 null 或空数组；
不能从当前文档继承标题、作者、日期或标识符来填齐字段。
只有 PDF 明确说明两者共用某项信息时，才可分别记录该值，
并为这种共用关系保留依据。

原文明确指向一个其他版本、但没有给出其详细书目信息时，
可以保留有实质内容的关系记录，target 中未知字段使用
相应空值，并在 issues 中说明信息缺口。
泛泛提到“以往各版”等无法区分的多个对象时，不猜测数量、
版号或逐一制造条目；将与身份提取有关的已知线索和无法
拆分的原因保留在 issues 中，不把多个未知版本伪装成
一个确定版本。

版本关系本身与 target 中的每项信息分别核对。
确认某个 DOI 或书目条目出现在 PDF 中，不等于已经确认
它与当前对象的版本关系；确认版本关系，也不等于已经
知道该版本的全部作者、发表状态和出版信息。
原文明确指向关联版本的参考文献条目可以作为其信息来源，
但只记录本次 PDF 实际提供的内容，不声称已经读取、比对
或核验了外部版本。

多个位置说明同一关联版本时，在身份与参照对象均可确认
一致后合并，保留必要的关系与出处；不能只按标题、作者或
不带版本后缀的编号合并。
同一版本的不同书目候选尚未消解时，在 issues 中保留
候选和冲突，不把每个候选都拆成一个已经确认的新版本。
不同日期、印次、载体或下载地址的出现，也不自动要求新增
版本条目；先判断它们是否确实描述不同的版本对象。

每条记录只表达 target 与当前 document 或 container
之间能够确认的直接关系，不在 target 内递归生成新的
relatedVersions，也不补造版本之间的完整演变链。
条目按关系在 PDF 中首次得到明确说明的顺序排列，不为
排序推断未知年份或版本先后。

没有可确认的关联版本时，relatedVersions 返回空数组。
所有依据来自本次 PDF，统一放入 metadata.sources，
分别关联 relativeTo、relations 和 target 中所支持的
具体内容；缺口、歧义与冲突统一放入 metadata.issues。
不从 Brief、术语表、符号表、已有文库记录、模型记忆或
未读取的外部页面补全，也不以关联版本的较完整信息覆盖
当前文档的身份。
```

### document.abstracts（原文摘要）：已确认（2026-09-08）

建议将旧的单个 abstract 字符串改为 document.abstracts 数组，以分别保留当前文档明确提供的不同语言或不同用途的文本摘要。本轮只扩展 document 的摘要字段，container 与关联版本 target 不新增摘要采集职责；此前已确认的提取边界保持不变。

| 字段 | 建议类型或取值 | 职责 |
|---|---|---|
| label | 原文字符串或 null | 整份摘要原有的标题或标签 |
| languages | 中文语言名称数组 | 根据实际摘要正文能够确认的语言，不由标题或界面语言推断 |
| completeness | complete / partial / unknown | 本次保留的摘要内容是否完整，与 document.coverage 分别判断 |
| segments | 下述分段数组 | 按原文阅读顺序保留正文、结构化小标题和可确认的连续文字 |

每项恰含以上四字段。每个 segments 元素恰含 heading（原文小标题或 null）与 text（非空原文正文字符串）。连续、无小标题的摘要可用单段保存全文和必要换行；结构化摘要按原文小标题分段；缺损两侧分段并由统一 issues 标记缺口，不把模型说明混入正文。已经确认存在摘要但没有可提取正文时允许 segments 为 []，须以 partial 和实际问题明确说明。没有可确认的摘要时 abstracts 为 []。

languages 使用能够确认的中文语言名称，不在本轮要求模型生成语言代码；后续界面如需代码，由应用依据确定的映射处理，不推断原文未提供或无法确认的语言变体。原文摘要仍保留原文语言，提示词使用中文不意味着翻译摘要。

```text
研究亮点和正文结论，不能仅因具有概括性就视为摘要。

摘要形式，并通过 sources 定位。
存在另行提供的独立文本摘要时，仍按本字段规则提取。

本轮摘要字段只放在 document 中。
所属出版物或其他版本的摘要不能填入当前文档，即使题名

需要说明原文中出现的其他摘要及归属疑问时，使用 sources

结构化摘要内部的 Background、Methods 等小标题属于
segments 中对应的 heading，不与整体 label 混淆。

根据实际正文判断，不根据论文题名、摘要标签、作者单位、

原文本身在同一份摘要中连续交替使用多种语言、无法按独立

不补译缺少的语言版本，也不将应用的中文输出要求理解为
需要把外文摘要翻译成中文。

heading 和 text。heading 为对应的原文小标题或 null；
text 为非空的原文正文字符串。

在 text 中保留必要的段落换行，不要求一句话拆成一个分段。

原文存在结构化小标题时，按原有结构保留对应分段及顺序。
不强制改成“背景、方法、结果、结论”等固定模板，不翻译

正文存在语法、拼写或事实上的疑问时，忠实保留原文；
提取疑问与必要说明放入 issues，不直接修正摘要。

可以整理不影响含义的跨行排版、空格和明确由排版造成的
单词断行，但不能机械删除连字符或改变数字、符号的组成。
保留段落、列表、结构化小标题与必要的公式结构；数学内容
按原文忠实转写，不重新推导或改成模型认为更正确的公式。
跨栏和跨页内容按能够确认的阅读顺序衔接，排除混入的
页眉、页脚或邻栏正文，不按文本抽取工具的顺序盲目拼接。

关键词列表、作者信息、版权说明等在摘要边界之外的内容，
不并入正文，也不因紧邻摘要而生成额外的主题标签。
原文明确属于摘要自身的附注或注册编号等信息应保留，
不能仅因格式不同就机械删去；边界不清时保留具体问题。

completeness 表示本次输出相对于这份原文摘要的完整程度，
取 complete、partial 或 unknown。
能够确认摘要起止边界，且各部分正文均已可靠保留时使用
complete；能够确认存在缺页、截断、不可辨认内容或其他

句子看起来完整、篇幅符合通常长度或 PDF 可以正常打开，

摘要完整程度与 document.coverage 分别判断。

摘要存在缺损时，保留能够可靠辨认的连续文字。
缺口两侧的正文分别放入 segments，不直接拼成原文未能
确认的连续句子或段落；在 issues 中关联相应分段，说明
缺口位置、性质以及边界是否可确认。
不在 heading 或 text 中插入“原文缺失”“无法辨认”等
模型说明，也不添加省略号来掩盖主动删节。
原文本身的省略号或缺损标记则按原样保留。

能够确认的 label 和语言分别保留，不能仅凭标签猜语言，
也不生成“暂无摘要”等占位正文。
没有找到可确认的当前文档摘要时，abstracts 使用空数组；
区分未找到、材料未包含相关页面以及归属未定等实际情况，

同一份摘要在不同位置重复出现且内容一致时，可以合并，
保留必要出处；不能只按语言或标签进行去重。
同一文档确实提供多份独立摘要时，即使语言相同也可分别
记录。尚不能判断是独立摘要、不同版本还是冲突候选时，
保留问题与候选，不为了容纳差异而擅自生成多个确定条目。
不同语言摘要的原文内容有差异时分别保留，不通过翻译、
改写或拼接使其一致。

摘要条目按在 PDF 中首次出现的顺序排列，各条目的分段按
原文阅读顺序排列；不根据应用语言或摘要长度改写顺序。
每份摘要的身份、版本归属、边界、语言判断、完整程度和
正文分段，通过统一的 metadata.sources 关联具体依据。
跨页摘要保留核对各部分所需的位置，不只用第一页的一个
出处笼统声称覆盖全部正文。

提取过程中产生的说明、发现的缺口或冲突统一放入
metadata.issues，与原文摘要内容分开保存。原文正文自身

输出遵循最终 JSON 与数学排版规则；保留原文语言和结构，
不附加评价、补充解释、模型生成的摘要或未读取的外部内容。
```

### metadata.sources（逐字段出处）：已确认（2026-09-08）

建议每条出处保留 pageNumber、locator、excerpt 三项定位与摘录信息，将元数据中的 supports 定义为非空数组，每项包含 fieldPath 和 explanation。这个调整只针对 metadata.sources：此前符号表与术语表中 supports 为中文字符串的已确认结构原样保留。元数据需要在同一出处下分别说明不同字段的支持关系。

| 字段 | 建议类型或取值 | 职责 |
|---|---|---|
| pageNumber | PDF 实际页序整数或 null | 从 1 开始，不超过 PDF 总页数；未知时不猜 |
| locator | 字符串 | 原文内的位置描述，没有可靠补充时为 "" |
| excerpt | 字符串 | 足以核对的短原文片段；视觉或不可转写依据可为 "" |
| supports | 非空数组 | 每项恰含 fieldPath 与 explanation，分别支持具体字段或关系 |

### 文库展示、排序与旧数据兼容：已确认（2026-09-08）

以下规则由应用执行，不属于模型提示词。本轮依据现有代码讨论行为：当前 ArtifactPanel 读取平铺元数据，编辑后自动将字段加入 _pinned；document_artifacts.rs 会将旧锁定值合并进新结果并以整体 source = model 同步；library_query.rs 的年份排序读取 publication_year，章节排序读取当前成果的 $.chapterNumber。新协议落地需同步这些读取与合并路径。

这部分是应用执行规则，不加入模型提示词。模型提取结果、人工修改和界面展示分别保存，每个展示值都能追溯到实际来源。

1. **保存提取原稿，单独维护人工修改。**

   每次模型输出通过完整校验后，保存为不可被后续编辑覆盖的提取版本。人工修改、钉住状态和显示偏好由应用另行保存；界面读取合并后的有效结果，同时保留模型原稿、旧值及修改来源。

   人工改过的值不能继续冒用原值的“已核验”状态。原文出处可以作为对照保留，但必须明确它支持原始提取值还是当前人工值。字段来源分别维护，不能因为一部分内容来自模型，就把整份合并结果统一标为 model。

2. **按来源和实际问题确定展示优先级。**

   默认顺序为：适用于当前对象的明确人工设置 → 当前修订的新结构结果 → 同一修订的旧记录 → 必要的显示占位。旧记录参与展示时注明“旧记录”，不反写进模型提取原稿，不升级为已由当前 PDF 核对的信息。

   新结果对某字段存在尚未消解的归属歧义或候选冲突时，显示对应的待核对状态，并保留旧值供比较；不能用旧值自动掩盖问题。明确的人工选择仍可生效，但它的人工来源和仍存在的原文差异需要保留。

   人工清空、隐藏与“尚未填写”分别保存，不能把明确清空视为缺失而再次自动补回。没有实际问题的正常空值使用简洁占位，不生成一串告警。

3. **各展示项按下面的归属读取。**

   | 展示项 | 默认规则 |
   |---|---|
   | 标题 | 读取 document.title。缺失且没有可用人工值或旧记录时，以文件名作为文库显示名称，并标明它是文件名；不写回原文标题。 |
   | 作者 | 只读取 document.contributors 中 role 为 author 的条目；按可确认的 order 保留顺序。没有作者但有编者或译者时，可以按其实际角色展示，不改称作者，不自动继承整书作者。 |
   | 所属出版物 | 读取 container.title，并保留期刊、论文集、整书或系列的区别；期刊名与出版社名分别显示。整书作为当前对象时，其书名就是 document.title。 |
   | 章节位置 | 读取 container.placement 中对应的章、节等原文编号。徽标避免无条件再包一层“第……章”，以免原文已经带有章名或编号标签。 |
   | DOI 等标识符 | 当前文档优先展示 document.identifiers；所属整书或关联版本的编号注明对象。多个编号保留载体和版本区别，不任取第一项作为唯一编号。 |
   | 出版与发行主体 | 根据 publishingEntities.role 分别标注出版者、出版品牌、发行或发布机构，不把所有名称统一标成出版社。 |
   | 摘要 | 选择一份已有摘要进行展示，保留其原文、标题、语言与完整程度；具体选择规则见下文。 |

   作者 order 无法确认时保留提取数组中的相对顺序，不把这种显示顺序标为已确认的署名排名。旧作者字符串继续作为旧值保存，不猜拆姓名、角色或集体署名。

4. **年份展示携带事件和对象说明。**

   对当前 document，自动选择的事件优先级建议为 publication → print_publication → online_publication → release。只从能够可靠取得年份的规范化 value 中读取，不从模糊的 dateText、编号或文件名猜年份。

   这是应用的展示选择，不声称所选年份适用于所有引用格式。卡片应能看出所选事件，例如“2025 · 发布”或“2024 · 在线发表”，不能把发布年份一律标为出版年份。

   同一优先级只有一个可确认年份，或多个记录都指向相同年份时，可以显示该年；存在不同年份且尚不能确定应采用哪次事件时，保留多个日期并显示待核对状态，不默认取最早、最晚或第一条，也不跳到较低优先级绕过这一问题。

   当前文档没有可用年份且不存在上述冲突时，可以继续查下一事件。章节或论文集文章仍没有可用年份时，可采用已确认直接所属整书或论文集的相应年份，并明确标为“整书出版”“论文集出版”等实际对象和事件。期刊或系列自身的历史年份不作为文章年份的自动来源。

   copyright、printing、receipt、submission、acceptance 等日期保留在详情，不自动代替默认展示年份。用户可以明确选择其他已记录日期用于展示，所选事件仍需标注；人工直接填写的年份作为人工值保留，不据此虚构一个新的原文日期事件。

   年份显示、筛选和排序使用同一份带来源的选择结果。旧 publicationYear 字段不承载被改名的发布年或所属出版物年份；兼容接口需要区分原有出版年份与新的展示年份，不能只换一个字段名就改变其含义。

5. **摘要按可读性、语言和原文顺序选择。**

   用户明确选择的摘要优先。自动选择先考虑有可读正文的条目，再优先匹配用户的摘要语言偏好；没有单独设置时使用界面语言，没有匹配时按 PDF 原文顺序选择其他可读条目。

   在同一语言优先级内，优先选择已确认完整的摘要；其余可读摘要按原文顺序选择，显示 partial 或 unknown 对应的完整程度说明，不将“未知”解释为更完整。

   一次展示一份摘要，不能混合不同语言、不同条目或不同版本的分段。结构化小标题原样保留；局部缺损按 textGap 呈现，位置不明时显示整份摘要的缺损提示。

   已确认存在摘要但没有可读正文时，显示实际情况；旧摘要仍可作为带来源标记的旧记录查看，不自动标为完整原文。没有摘要时保留缺失状态，Brief 仍按自己的用途单独展示。

   用户选择的是某个具体条目时，新版本找不到可靠对应项应保留原选择的记录并说明变化，不能无提示地把选择绑定到同一下标的另一份摘要。语言偏好与钉住具体内容是不同操作。

6. **排序与显示保持一致。**

   章节排序从明确的 placement.chapterNumber 或相应人工设置读取原文编号，再由应用生成确定性的排序键。沿用分段整数的比较原则，例如 1.2 排在 1.10 之前；罗马数字、字母编号等只有在应用明确支持相应解析规则后才参与自动比较。

   不可解析的原文编号仍照常显示，不丢弃或改成猜测数字。缺少年份或无法解析章节编号的条目，在升序和降序中都放在可排序条目之后，并使用稳定的次级顺序。

   数据库查询、文库卡片和内存适配器采用一致规则。排序不能仍读取一套过期的平铺值，而界面显示另一套新结构结果。

7. **旧数据保留原貌，人工锁定保留效力。**

   切换到新协议前，保留原 metadata 内容、数据库旧字段、人工编辑与 _pinned 信息。按明确的协议版本识别新旧成果，不能只凭某个同名字段猜测格式；不要求用户重新生成才能继续查看旧记录。

   能够明确对应的新旧字段可以由应用建立读取映射，同时保留来源。旧 authors、publicationYear、bookName、doi、isbn、abstract 等信息，不能仅因字段名称看起来相近，就自动补成已确认角色、日期事件、版本归属或摘要完整程度。

   旧钉住字段优先作为人工设置继续生效；尚不能可靠映射到新结构时，保留为带来源的兼容覆盖值。尤其不能为了安放旧年份创建一个出版事件，或为了安放旧 ISBN 虚构所属整书。

   解锁表示恢复自动更新，不删除旧值和修改历史。重新生成保留新的模型原稿，钉住值继续覆盖其明确作用范围；不能把整个父对象都锁住来回避对局部字段的处理。

8. **人工编辑和新版本不能破坏关联。**

   数组条目由应用维护稳定身份。可靠确认对应关系后再迁移人工设置，不能只凭数组下标、姓名、题名或编号类型匹配。无法可靠对应的人工内容保留并明确标示，不能丢弃，也不能贴到另一个看似相近的对象上。

   调整作者列表、版本条目、摘要分段或问题条目时，同时处理相关 sources、issues 和 textGap：可以可靠重建关联则更新，否则明确使受影响关联失效，保留原始版本供核对。

   文库显示名称、语言等偏好可按文库文档保存；与某份 PDF 事实有关的修正和出处应记录所属 revision。更换 PDF 时保留旧人工信息及其来源，不无条件宣称它仍是新 PDF 的事实，也不静默删除。

   新结果通过结构和关联校验后，再一致地更新当前成果、展示和排序所需的数据。生成失败、响应截断或校验失败时，保留现有可用版本，显示任务状态，不用空元数据覆盖当前记录。
