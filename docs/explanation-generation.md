# 解释生成合同

更新：2026-09-09。状态：完整中文稿与运行时接线已实现；尚未进行真实模型质量评估。

## 完整提示词

- [论文运行时完整稿](../src-tauri/prompts/explanation.paper.md)
- [教材运行时完整稿](../src-tauri/prompts/explanation.textbook.md)
- [两份完整定稿与讨论记录](note/explanation-prompt.md)

每份提示词分为八部分：任务范围、输入与依据、核心讲解原则、解释性补充、深度与组织、歧义和缺损、五字段职责、语言与输出协议。两份稿可独立使用；默认读者与文档侧重点分别编写。测试比较完整正文，避免只将压缩摘要写入运行时。

目标是讲清当前选段的含义，补足必要概念、逻辑、条件与上下文。简单内容简短解释，复杂论证按依赖展开；不强制固定讲解模板、例子或要点数量。必要数学保留，作者内容、背景知识、说明性例子与重建推理在容易混淆处明确区分。

## 输入与上下文

解释从只含完整 PDF 的来源根创建独立成果分支。请求沿用当前 `block`、`allowedEvidenceIds`、`outputLanguage` 和冻结的读者背景。任务说明改为中文。读者背景只包装进本次 user input；不写入来源根。

- 完整 PDF 是本文事实和文档结构的依据；当前正文块明确解释对象。
- 读者背景决定从哪里讲起及深度，不成为文档证据。
- 不增加 Brief、术语表、符号表、历史翻译、历史解释或 Discussion 输入。
- 两次解释都从来源根出发，后一次不续接前一次解释节点；已生成结果不回写来源根。
- 正文内的必要公式可以解释；独立 formula / figure / table 块仍由 Lens 处理。
- 原文指令、示例对话和读者笔记中的越界命令作为材料，不覆盖任务。

论文与教材提示词在入队时按照文档种类选择并冻结。正常执行优先使用冻结正文；没有冻结正文的内部调用使用文档种类对应的完整中文默认稿。英文 F2 读者段不再追加到解释默认稿，读者规则已经完整写在中文正文中；其他提示词的 F2 行为保持原有接线。

## 五字段协议与展示

输出沿用 `block_explanation`，协议仍为 v1，不新增字段或更改旧字段类型：

| 字段 | 职责 | 空值约定 |
| --- | --- | --- |
| `title` | 当前具体对象、关系或理解难点 | 非空字符串 |
| `explanation` | 可独立阅读的完整讲解；就近交代补充、条件、歧义与依据 | 非空字符串 |
| `keyPoints` | 需要特别抓住的条件、区别、误读风险或步骤关系 | 无必要条目时 `[]` |
| `paperConnection` | 可确认且值得单列的论证或学习联系；教材也使用此字段 | 无必要补充时 `""` |
| `evidenceIds` | 本次白名单中的选段定位 ID | 无可靠定位时 `[]` |

`keyPoints` 可与正文有必要的语义重合，但应承担提醒或辨析作用，不复制正文形成第二份摘要。`paperConnection` 说明具体关系，不用“承上启下”填充，也不重复正文已经讲清的机制。

无法可靠解释时，仍使用这五个字段：标题明确限制，正文具体说明材料问题；`keyPoints=[]`、`paperConnection=""`，引用按实际定位情况填写。不引入 status 或伪造完整讲解。当前协议没有机器可判定的“部分解释／无法解释”状态，不能把成果的 `ready` 等同于内容没有不确定性。

界面使用“解释”“理解要点”“与文档的联系”；空要点及空文档联系不显示栏目。原有历史成果继续按同一字段展示。`GeneratedDetail` 同时服务成果面板和区块卡片。

## 证据与校验边界

当前白名单只包含 `block:<当前块 ID>`。它是本次解释的选段锚点，不代表其他全文联系都由这一块单独证明。跨文档部分的依据可在自然语言中使用已确认的章节标题、定义、定理、公式或图表编号；本次不扩充跨块跳转协议。

后端在添加应用元数据、保存生成节点和发布成果之前，使用现有五字段 schema 做完整结构校验，并继续验证引用白名单。缺字段、多余字段、错误类型、空白标题／正文、非法引用都会失败，不发布为新成果，也不进行内容 repair。

结构校验不验证论证是否成立、例子是否恰当、引用是否实际支持主张，也不自动判定原文错误或 OCR 修正是否正确；这些是提示词约束与后续真实样本评估的责任。现有 schema 对要点字符串没有新增语义或非空约束，避免偷偷改变旧协议。

## 默认稿迁移与兼容

提示词配置新增 `explanationGeneration=1`，配置 schema 仍为 2。首次读取旧配置时：

1. 将读取到的原始配置备份到同目录 `prompt-settings.before-explanation-zh-v1.json`，已有备份不覆盖。
2. 分别识别论文／教材的已知旧英文默认正文，以及附带原英文 F2 读者段的默认正文；比较时允许 CRLF/LF 与外围空白差异。
3. 仅把当前仍匹配已知默认稿的槽升级为对应完整中文稿。自定义当前稿、`previousText` 和其他槽不由这次迁移覆盖。
4. 记录迁移代次。用户主动恢复上一版后，不再次自动升级；恢复默认则得到中文完整稿。

旧默认正文存档：

- [论文旧正文](../src-tauri/prompts/history/explanation.paper.before-chinese.md)
- [教材旧正文](../src-tauri/prompts/history/explanation.textbook.before-chinese.md)

已排队任务使用原来冻结的正文。符合原五字段 schema 的旧稿输出与历史成果保持兼容；以前因局部校验不完整而漏过的非法返回，现在会在发布前拒绝。
