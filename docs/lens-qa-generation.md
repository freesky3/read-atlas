## 2. 追问的讲解目标

围绕当前问题找到读者的理解断点，按反馈调整讲法。问含义时讲清对象和作用，问推导时补必要步骤，问图表时定位真实区域或单元格，问比较时核对条件与口径。遇到“还是不懂”，换具体对象、小例子、组块分解或必要背景，不只做同义改写。

正文包含九部分：身份与目标、材料用途、识别卡点、改变讲法、公式／图／表的具体回应方式、独立判断与纠正、多轮节奏、材料不足与引用、输出检查。

- 读者需要完整解答、提示、逐步推进或检查自己的推理时按请求回应，不强制测验、练习、结尾反问或下一步问题列表。
- 区分讲解过、读者自述理解和在某个具体问题中展示理解；不能从“继续”推断已经掌握背景。
- 已有 Lens 和历史回答是待核对的生成内容。每轮重复输入的原 Lens 不覆盖本分支有依据的纠正；最新说法和双方同意也不自动等于事实正确。
- 可以指出并修正原解析错误，但不能声称已修改 Lens 卡片、PDF 或其他成果。追问不写回原卡片。
- partial／unavailable 不禁止继续提问。可以解释能独立回答的概念，同时保留无法确认的具体符号、视觉细节或数值。

## 3. 实际输入与续接

1. `ask_lens` 每轮读取当前文档种类的追问设置和读者背景。本次请求构造后使用该份正文；它不从初始 Lens 生成任务继承冻结的追问稿。未提供覆盖正文时，模块回退到同一种类的完整新默认稿。
2. 当前请求包含中文 task、question、原 Lens 内容 lens、allowedEvidenceIds；Reader context 包装在 user_input 前。原 Lens 可能是 v1、v2、部分可解释或暂无法解释的成果，均可追问。
3. 初次提问从选定 Lens 版本的 provider 节点续接；带 parentId 时只允许续接同一 Lens、同一 route、model 和 epoch 中的 assistant 回答。parentId 为空表示从该 Lens 原节点开始，不自动续接别的分支。现有 UI 通常传入最新 assistant 的 ID。
4. 历史依赖 provider 的远端分支续接；本次没有新增本地完整历史重放、压缩或跨版本记忆。提示词只允许使用实际可见的历史，不承诺丢失的上下文已经恢复。
5. 提供当前 PDF 路径、远端文件和 previous_interaction_id；本轮 inline_images 为空。不会重新发送 crop，也不会自动读取本地截图路径、当前鼠标或新框选。原分支图片是否仍可见由真实 provider 上下文决定，提示词不假设它必然完整保留。
6. 不自动传入 Brief、术语表、符号表、Discussion 或其他成果。Reader context 决定解释起点与深度，不构成原文证据。

## 4. 输出与校验

输出仍为 v1 两字段合同，不增加状态、标题、固定栏目或额外问题数组。

| 字段 | 规则 |
| --- | --- |
| answerMarkdown | 非空自然回答；按需要包含直觉、例子、步骤、纠正或具体局限 |
| evidenceIds | 字符串数组；只能使用当前对象的 allowedEvidenceIds，可为空 |

本地完整核对两个字段、类型、非空正文、额外字段和证据白名单；不能只校验某个字段而忽略多余的模型输出。保留现有 JSON 对象提取能力，旧模型返回代码围栏时仍可解析；不运行写入侧 Markdown 归一化，保存解码后的换行与 LaTeX 原文。正文沿用现有 Markdown 渲染。

输出字段没有变化，自定义旧稿仍应遵守这个本来就声明的 strict schema。旧稿若曾输出未声明的额外字段，现在会被本地拒绝。校验不检查数学推理、图像解读、读数或引用在语义上是否正确，也不证明模型必然保持已纠正的认识。

结构化 evidenceIds 在现有路径中用于校验，`lens_qa` 持久化的回答正文为 answerMarkdown，不新增单独的证据列。正文中的块引用也应遵守白名单；本地结构校验不扫描正文中的全部引用标记，不能把提示词约束宣称成完整的程序校验。

## 5. 发布、失败与隔离

- 合法回答保存为当前用户追问的 assistant 子节点，保留对应 provider 节点并记录 receipt；不修改原 Lens 内容、初始成果版本或 Discussion 消息。
- 模型已返回但 JSON／字段／引用校验失败时，不发布 assistant 回答，将返回的 provider 节点标记为 invalid，并把本次 receipt 记录到已保存的用户追问上。保留用户问题，沿用现有错误反馈。
- QA 不使用 Lens 生成的 repair 槽，也不新增自动修复或额外付费重试。
- 远端不可用、网络错误及数据库写入失败继续沿用已有错误路径；本轮只补全已返回无效输出的节点与费用记录，不声称完成了所有异常恢复。

## 6. 默认稿迁移与恢复

1. 提示词配置 schema 仍为 2，新增 `lensQaGeneration=1`；输出协议仍为 v1，Workspace 与数据库 schema 不变。
2. 首次读取旧配置时，保存原始文件至 `prompt-settings.before-lens-qa-zh-v1.json`，已有备份不覆盖。只将论文／教材已知旧默认正文（含可选旧英文 F2 段、CRLF 差异）替换为完整新稿。
3. 自定义当前稿和 previousText 保留；恢复上一版后不会被重复升级。原始两份正文归档在 prompts/history/lens-qa.*.before-chinese.md。本轮开发不直接修改用户真实设置文件。
4. 两份新稿已内置读者原则，不再追加英文 F2 读者段；F2 请求侧读者包装仍有效，逐轮读取方式不变。
5. `{output_language}` 不是本槽必填项。正文语言按读者本轮要求、当前问题主要语言、分支语言、原 Lens 语言依次判断，仍不明确时用中文。
