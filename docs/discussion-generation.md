讨论稿各九部分：身份与目标、材料用途、直接回应与深度、按问题选择方式、判断与纠正、推导与探索、多轮推进、引用定位、表达与不足处理。压缩稿各八部分：任务、输入来源、优先保留、修正与状态、追溯、取舍、三个字段、输出协议。每份可独立使用，定稿与运行时正文逐字对应；不在运行时换成缩略版。

讨论围绕读者的问题推进，默认直接回答，需要时解释、推导、辨析或探索。论文版强调研究问题、方法、证据和结论边界；教材版强调概念关系、例题、学习困难和迁移。读者要求提示时控制提示层级，要求完整解答时充分回答，不强制苏格拉底反问、固定模板、练习或结尾邀请。

## 讨论输入与运行路径

`send_chat` 每轮按当前文档种类读取 `discussion` 设置并固定到该次生成；不入 Job。Reader context 仍每轮现读并包装到本次增量与恢复输入，完整中文默认稿已经包含读者规则，不再追加英文 F2 段。自定义当前稿原样使用。

- 原生 PDF 是本文事实的首要依据。
- 本轮用户问题决定任务，阅读页只提供位置线索。
- 本轮引用块由后端加载；历史消息带各自不可变块快照。
- 历史消息带 `status`，表示生成是否完成，不表示内容已验证。失败或取消内容若出现在所选本地路径中，不能在语义上被自动视作完整答案。
- 普通新问题从当前分支继续；重新生成沿用现有 sibling user turn 机制，使用目标用户问题及其存储快照，不带失败回答作为新问题。
- `discussion_turn_input` 为普通发送和重新生成统一构造当前问题、阅读位置和精确引用白名单；无块时明确白名单为空。
- 不新增 Brief、术语表、符号表、论证地图或其他分支历史的自动注入。用户实际带入的成果作为线索，不能自动提升为原文证据。

Gemini 有有效父节点时沿用增量续接；其他情况沿用 PDF 加本地分支恢复。流式 Markdown、取消、发布与计费路径保持现有机制。历史消息、题设或 PDF 中的命令作为材料使用，不能改变本次任务。

## 引用与内容边界

论文与教材都区分原文陈述、基于材料的推断、一般背景知识和待验证设想。观点被赞同、反复出现或进入压缩记录，不提升其学术可信度。纠正需保留正确表述与依赖变化，未解分歧不得被强行合并。

- `[p. N]` 只用于可靠确认的 PDF 物理页序号，从 1 开始；不能用当前阅读页兜底。
- `[block: BLOCK_ID]` 只使用本轮获准的块 ID。历史块快照用于理解先前交流，不自动扩充本轮白名单；重新生成使用目标问题存储的获准快照。
- 论文特定主张和结果尽量给可靠原文定位；教材一般概念、自拟例子与独立推导不强制引用，具体归属于教材的内容仍应有依据。
- 无可靠跳转位置时可使用确知的标题、定义、定理、公式或题号，不编造标记。
- 后端引用提取保留原有页数范围和块白名单检查。它不验证某页是否真正支持该主张，也不会自动删除自由文本中的所有非法引用字样。

新提问使用提交时的应用语言；历史分支、提问文本和自定义提示词不改变这一语言。讨论与压缩提示词在提交时一起冻结，切换界面不改变已经进行的回答。历史正文保留原文，详见 [语言合同](bilingual-ui.md)。数学、代码与列表直接遵循现有 Markdown 渲染合同；未修改渲染器。

## 压缩输入与认识状态

`discussion_compaction` 按文档种类现读设置，独立调用完整 PDF 与当前路径的 `sourceMessages`，不追加 Reader context，不从其他成果分支续接。

每条源消息包含 `id`、`role`、`status`、`content`、`blockQuotes`。当前待回答问题不额外注入压缩；若提供的历史本身含未回答问题，只保存为未决事项。PDF 用于理解已讨论对象或核对相关内容，不把新发现写成双方早已确认的认识。

优先保存当前目标、必要定义和条件、有效修正、关键认识的来源与状态、未决事项及实际约定的下一步。必须区分：

- 原文报告、推断、假设与双方同意。
- 提出计划、同意计划、实际执行与取得结果。
- 已讲解、读者表示理解与在某个任务中展示理解。
- 已解决、部分解决、暂缓、撤回与材料缺失。

对取消、失败或未完成消息，不补写尚未给出的结论。`complete` 也不等于正确。历史引用保存为明确的来源线索，不转成后续可点击块权限。

## 三字段协议与恢复

模型输出仍为 v1 的三个字段，不新增键或改变类型：

| 字段 | 内容 | 空值约定 |
| --- | --- | --- |
| `summaryMarkdown` | 可独立续接的当前目标、上下文、进展、修正、分歧及约定下一步 | 非空字符串；无历史时如实说明 |
| `retainedClaims` | 重要认识、约定或中间结果；每项保留必要条件、来源与状态，不全部视作确定事实 | 非空字符串数组，可 `[]` |
| `unresolvedQuestions` | 具体待回答、核实或完成的事项及实际卡点 | 非空字符串数组，可 `[]` |

发布前验证对象恰好具有三个键、正确类型、非空摘要及非空数组条目。解析仍容忍旧稿返回代码围栏或前后说明，但最终默认稿要求纯 JSON；无效结构失败，不进行内容 repair。

成功压缩后，当轮恢复输入现在包含三个字段的完整 JSON，而不是只保留 `summaryMarkdown`。因此，仅保存在关键认识或未决问题清单中的内容，也能进入非 Gemini 恢复及远端资源失效后的重建。当前问题、Reader context 和本轮白名单继续显式附在压缩记录之后。摘要本身仍要求独立可读，避免关键修正只藏在某个数组中。

UI 的压缩完成事件继续用 `summaryMarkdown` 展示。完整 Artifact 保存三字段，应用自行追加源消息 ID 与数量；依赖快照保存源角色、状态及正文、引用快照的哈希。这些元数据不由模型填写，不改写原消息。

本次不重构压缩触发与历史续接策略：仍至少八条历史消息且估算超过窗口 80% 时触发；有可续接远端节点时仍使用既有机制。摘要变短不等于服务端祖先历史已移出上下文，实际 token 减少与缓存效果需要 receipt 和真实 provider 验证，不能仅凭本次提示词修改保证。

## 默认稿升级与兼容

配置增加 `discussionGeneration=1`，配置 schema 仍为 2，输出协议仍为 v1。首次读取旧配置时：

1. 先将读取到的原始配置备份为同目录 `prompt-settings.before-discussion-zh-v1.json`，已存在的备份不覆盖。
2. 对讨论与压缩的论文、教材槽分别识别已知旧默认稿；讨论也识别附带旧英文 F2 段的版本。比较允许 CRLF/LF 及外围空白差异。
3. 仅升级仍匹配已知默认稿的当前正文；自定义当前稿、`previousText` 不覆盖。
4. 记录迁移代次，主动恢复旧稿后不再次自动升级；恢复默认得到完整中文稿。

四份旧基础稿存放在 `src-tauri/prompts/history/discussion*.before-chinese.md`。历史消息、压缩成果、用户配置的自定义正文与上一版不重写。正在运行的讨论保留开始时读取的系统正文，后续发送再读取当前设置。

扩展既有测试覆盖额外字段、缺字段、空白条目、非法类型拒绝，重生成输入保留原问题及块快照，数据库路径加载状态，以及非法块和越界页码不成为有效引用。测试使用本地临时数据库和纯请求构造，不访问用户文库或真实模型。

结构与接入测试不能证明回答质量、引用的语义支持、压缩无遗漏或研究判断正确。后续真实样本应覆盖论文与教材、长分支、明确纠正、未验证假设、提示式解题、部分理解、跨语言追问和材料缺损。
