# 精读路线生成合同

## 目标与完整提示词

2026-09-09 定稿：精读路线像熟悉当前文档的导师，指导读者按照合理的理解顺序亲自阅读原文，逐步加深理解。主要价值是“先读哪里、怎样读、当前读到什么程度、何时返回处理细节”，不以内容总结、结构展示或快速筛选作为默认目标。

- [完整定稿：论文版与教材版](note/reading-roadmap-prompt.md)
- [论文运行时提示词](../src-tauri/prompts/reading-roadmap.paper.md)
- [教材运行时提示词](../src-tauri/prompts/reading-roadmap.textbook.md)

两份正文各分九部分：身份与目标、材料与读者、顺序安排、分遍衔接、任务设计、导师口吻、节奏、字段职责、输出与材料不足处理。定稿文档与运行时逐字一致（仅忽略换行编码及末尾换行），不把完整讨论缩写为短版指令。

论文参考 [Keshav《How to Read a Paper》2016 版本](https://systems.cs.columbia.edu/ds2-class/papers/keshav-paper.pdf) 的逐遍深入思想。可选 Pass 0、具体任务规则、教材适配和 JSON 字段是本应用设计，并非原文规定。

| 阶段 | 论文 | 教材 |
| --- | --- | --- |
| 可选 Pass 0 | 必要的前置对齐 | 即将阻断学习的基础准备 |
| Pass 1 | 建立阅读方向 | 建立学习方向与范围 |
| Pass 2 | 按理解依赖读懂主体 | 连接概念、推导与例题 |
| Pass 3 | 返回关键细节，核对与重建 | 独立应用、重建与查漏 |

第三遍属于默认精读路径，不只面向审稿或复现。相同对象可以多次出现，但每次新增阅读深度。路线覆盖主体章节，依据内容依赖跳读与回看；无图论文可以围绕定理、算法或段落。任务可以给必要提示，不代填完整解释或自检答案，不强制每项一至三问。时间是粗略安排，勾选是读者自记进度，不是自动掌握判定。

## 输入与来源根

新任务入队时固定以下内容：

1. 同一次提示词配置读取中的 `roadmap`、`paperRoot` 与 `documentKind`。
2. 对应文档种类的 `responseSchema`。
3. 可选当前 Brief 的 `artifactId`、`version` 和完整 `content`；没有 Brief 时也冻结其缺席状态。
4. 原有 Reader context 包装文本。
5. 原有 Provider route、模型和 revision。

全文 PDF 是事实依据，Brief 只是辅助阅读材料，读者背景影响起点和节奏。新任务执行时不重新读取已改变的 Brief；老任务缺少 `briefSource` 时保留执行时读取的历史行为。冻结的旧或自定义路线正文原样使用，不用新默认稿覆盖；老任务缺少根提示词或 schema 时按对应文档种类补齐。

生成复用 `ReadingArtifactModule::call_from_paper_root`：来源根只接收完整 PDF 与确认请求；Brief、Reader context、路线任务说明只进入独立 Artifact 旁支。再次生成从同一来源根出发，不续接上一条路线，不把路线成果写回 `context_roots`。过期远程资源沿现成机制重建根后重试一次；不因此进行内容修复调用。

当前精读路线请求不提供 OCR 目录。只允许可确认的 PDF 物理页序，省略 `blockId`。原文标题、章节或对象编号能够辨认但页码不可靠时，可以在任务文本中定位并使用 `evidence: []`；不制造跳转页。历史成果已有的块跳转仍可显示。

## 字段与兼容

结构版本继续为 `version: 1`，沿用任务和阶段字段。新 schema 将论文原先必填的两个附加栏目改为可选；历史成果仍按原字段展示。新增结构校验适用于本次执行，不回写或重验旧成果。

| 字段 | 定稿职责 |
| --- | --- |
| `paperTitle` | 当前实际阅读范围的标题，教材沿用同一键 |
| `passes` | 执行顺序；阶段含编号、标题、说明、时间参考、衔接标准和任务 |
| 任务 `text` | 阅读位置、动作、必要的顺序理由、观察重点与回看安排 |
| `completionCriteria` | 当前应达到的具体理解程度 |
| `selfCheckQuestions` | 确有帮助的自检问题，无需提问时 `[]` |
| `required` | 对当前主线是否必要，不等于阶段编号或耗时长短 |
| `evidence` | 可靠原文定位，允许 `[]` |
| 可选 `elevatorPitch` | 界面“复述自检提示”，不再强制三十秒或代写总结 |
| 可选 `oneChart` | 界面“优先精读对象”；可以是图、表、定理、算法、定义、例题或段落 |
| 教材可选 `learningObjectives` / `prerequisites` | 对应当前范围的学习目标和必要知识，不生成整门课程大纲 |

保留 `oneChart` 的历史键名以兼容既有成果；其中仍为 `label`、`page`、`reason` 与可选 `blockId`。本次未提供 OCR 目录，模型实际输出 `blockId` 将被拒绝。不能确认页码或没有合适对象时省略整个 `oneChart`，不填 `null` 或假页码。

材料完全不足时，提示词要求仅返回说明限制的 Pass 0，空任务，省略附加栏目。仍发布为普通成果 `ready`，没有新增机器可判定的 unavailable 状态。UI 以说明文本表达限制，不能把 ready 或零任务误解成完成学习。

## 校验、响应保留与恢复

`roadmap_module.rs` 负责响应 schema、输入组装、解析、校验与生成；`lib.rs` 保留 IPC 和任务路由。原有 Markdown 组件、进度表、不可变成果与重新生成入口继续使用。

发布前检查：

- 包括可选字段在内的类型、必填字段、额外字段；关键文本非空。
- version 为 1；阶段编号为 0 至 3 且不重复；任务标识在路线内唯一。
- 正整数任务时间；定位页至少为 1，有已知 PDF 页数时不得越界。
- 没有提供 OCR 白名单时不得出现 `blockId`。

结构校验不能证明具体页码语义正确、阅读顺序科学、任务足够覆盖全文或文字真正具有导师风格。正常三遍的完整覆盖与返回深度由提示词约束，不强制修改已有自定义阶段安排。沿用旧 JSON 解析器对围栏或前缀的容错，不修改已解析的正文排版与数学表达。

调用成功后先把原始正文、根 epoch、父节点和用量记录保存到任务 checkpoint，再校验、存旁支节点并发布。校验失败仍保留已发生的用量。恢复同一任务使用保存的响应，不再付费生成或修复；发布失败可以在本地问题解决后重试。已发布成果通过任务标识找到并直接返回，避免重复发布同一次结果。重新生成是新任务，从来源根建立新的独立旁支。
